## 이 장의 위치

1장은 **단언**(assertion)이 무엇이고 언제 타당한지를, 2장은 **명령**이 무엇을 하는지를
정했다. 3장은 그 둘을 잇는다. 명령 앞뒤에 단언을 놓아 "이 상태에서 시작하면 저 상태로
끝난다"를 말하고, 그런 주장을 **증명하는 규칙**을 세운다. Hoare 논리다.

이 장이 1·2장과 다른 점은 새 대상을 거의 만들지 않는다는 것이다. 명세의 뜻은 2장의
`Comm.eval` 위에 정의하고, 규칙의 건전성은 1·2장의 정리로 증명한다. 정확히 어느 정리가
어느 규칙을 받치는지가 이 장의 골격이다.

| 규칙 | 받치는 정리 |
|---|---|
| 대입 공리 `{q/v→e} v := e {q}` | 명제 1.4 (`substitution_single`) |
| 결과 규칙 (전제 강화 · 결론 약화) | §1.3 의 `Stronger` |
| 조건 규칙 | §2.2 의 `boolExp_eval_iff` |
| `while` 규칙 (부분 정확성) | §2.4 의 `scott_induction` + `Chain.flat_lub_mem_range` |
| `while` 규칙 (전체 정확성) | 정수 위의 정초 귀납 (`Nat` 측도) |
| 변수 선언 규칙 | 명제 1.1 (`coincidence_assert`) + `restore` |

지나간 것인데, `while` 규칙의 건전성이 바로 그 원리다.

## §3.1 명세의 구문과 뜻

### 두 종류의 명세

```
{ p } c { q }     부분 정확성(partial correctness)
[ p ] c [ q ]     전체 정확성(total correctness)
```

`p` 는 사전조건(precondition), `q` 는 사후조건(postcondition)이다. 둘 다 1장의 단언이다.

부분 정확성은 "끝나면 `q` 다" 이고 전체 정확성은 "끝나고, `q` 다" 다. 차이는 **비종료를
어느 쪽으로 세느냐**뿐이다.

### 뜻 — 2장 위에 그대로

2장의 `Comm.eval : Comm V → State V → SigmaBot V` 가 있으므로 새로 만들 것이 없다.

```lean
/-- 부분 정확성. `c` 가 `σ` 에서 끝났다면 그 상태가 `q` 를 만족한다. 발산하면 공허하게 참. -/
def PartialCorrect (p : Assert V) (c : Comm V) (q : Assert V) : Prop :=
  ∀ σ : State V, ⟦p⟧ₐ σ → ∀ τ, c.eval σ = some τ → ⟦q⟧ₐ τ

/-- 전체 정확성. `c` 가 `σ` 에서 반드시 끝나고 그 상태가 `q` 를 만족한다. -/
def TotalCorrect (p : Assert V) (c : Comm V) (q : Assert V) : Prop :=
  ∀ σ : State V, ⟦p⟧ₐ σ → ∃ τ, c.eval σ = some τ ∧ ⟦q⟧ₐ τ
```

표기는 `⦃p⦄ c ⦃q⦄` 와 `⟬p⟭ c ⟬q⟭` 처럼 Lean 이 받아 주는 괄호를 쓴다. 책의 `{ }` 와
`[ ]` 는 Lean 에서 이미 다른 뜻이다.

둘의 관계는 정의에서 바로 나온다.

```lean
theorem TotalCorrect.toPartial : TotalCorrect p c q → PartialCorrect p c q
theorem partial_and_halts_iff_total :
    PartialCorrect p c q ∧ (∀ σ, ⟦p⟧ₐ σ → (c.eval σ).isSome) ↔ TotalCorrect p c q
```

### ★ `⊥` 는 모든 사후조건을 만족한다

부분 정확성의 정의를 `Σ⊥` 의 눈으로 다시 읽는다.

```
"c.eval σ 가 q 를 만족한다"  :=  c.eval σ = ⊥  ∨  (c.eval σ = some τ ∧ ⟦q⟧ τ)
```

`⊥` 가 아무 사후조건이나 만족한다는 것은 정보 순서에서 `⊥` 가 맨 아래에 있다는 것의
논리적 판이다. 정보가 없으니 어떤 주장과도 어긋나지 않는다.

이 관찰이 이 장의 가장 깊은 지점과 바로 닿는다. **부분 정확성은 사슬의 극한을 통과한다.**

```
∀ n, (dₙ σ 가 q 를 만족)   ⟹   (⨆ₙ dₙ) σ 가 q 를 만족
```

`Σ⊥` 가 평평하므로 극한은 사슬의 어느 항과 같다 (§2.3 의 `Chain.flat_lub_mem_range`).
그 항에서 성립하던 것이 극한에서도 성립한다. §2.4 의 말로 부분 정확성은 **허용
가능(admissible)** 하고, 그래서 Scott 귀납법을 쓸 수 있다. `while` 규칙의 건전성이
정확히 그 자리다 (§3.5).

전체 정확성은 그렇지 않다. 사슬 `⊥ ⊑ ⊥ ⊑ ⊥ ⊑ ⋯` 의 모든 항이 "끝나고 `q`" 를 만족하지
않는데 극한도 `⊥` 라 역시 만족하지 않으니 이 예는 무해하다. 문제는 반대 방향이다.
`while` 의 근사열 `Fⁿ(⊥)` 은 처음 몇 항이 발산하다가 어느 항부터 끝나는데, "끝난다" 는
주장은 "어느 단계부터" 를 말해 주지 않으면 극한으로 올라가지 않는다. 그래서 전체 정확성의
`while` 규칙은 Scott 귀납법이 아니라 **정초 귀납**을 쓴다 — 단계를 세는 측도가 규칙에
들어온다 (변항, §3.5).

> 2장의 두 귀납 원리가 3장에서 각각 한 규칙씩 받친다. Scott 귀납법은 부분 정확성을,
> 측도 귀납은 전체 정확성을. 2장에서 `while` 을 다룰 때 두 원리를 번갈아 썼던 것이
> 우연이 아니었다.

### ★ 단언은 구문인가 의미인가 — 둘 다

1장의 단언은 구문 `Assert V` 이고 뜻은 `⟦-⟧ₐ : Assert V → State V → Prop` 이다.
명세의 뜻은 `⟦p⟧ₐ` 만 쓰므로, 사실 **의미 술어** `P : State V → Prop` 만 있으면 정의된다.

```lean
/-- 의미 판. 단언이 상태 위의 술어다. -/
def PartialCorrectS (P : State V → Prop) (c : Comm V) (Q : State V → Prop) : Prop :=
  ∀ σ, P σ → ∀ τ, c.eval σ = some τ → Q τ

/-- 구문 판은 의미 판의 특수 경우다. -/
theorem PartialCorrect_iff : PartialCorrect p c q ↔ PartialCorrectS ⟦p⟧ₐ c ⟦q⟧ₐ := Iff.rfl
```

둘을 다 두는 이유가 있다.

- **규칙은 구문 판에 대해 세운다.** Hoare 논리의 요점은 대입 공리처럼 단언의 **구문**을
  조작하는 규칙이고, 그것은 `Assert` 위에서만 뜻이 있다. `q/v→e` 는 구문에 대한 치환이다.
- **예제는 의미 판이 필요할 때가 있다.** 빠른 거듭제곱의 불변식 `y · xᵏ = aⁿ` 에는
  거듭제곱이 드는데, 1장의 `IntExp` 에는 `+`·`-`·`×` 뿐이다. `Assert` 로 못 적는다.
  의미 단언 `fun σ => σ y * σ x ^ (σ k).toNat = ...` 은 적을 수 있다.

두 번째가 §3.10 의 **표현력** 논점의 실물이다. 단언 언어가 필요한 불변식을 적을 만큼
풍부해야 완전성이 서는데, 우리 `Assert` 는 그 정도가 아니다. 그것을 억지로 감추지 않고
"이 예제는 의미 단언으로 한다" 고 드러내는 편이 배우는 데 낫다.

의미 판의 규칙들은 치환이 함수 적용으로 바뀌어 더 단순하다.

```
{ fun σ => Q (σ[v := ⟦e⟧ σ]) }  v := e  { Q }
```

구문 판의 대입 공리 `{ q/v→e } v := e { q }` 는 여기에 명제 1.4 를 붙인 것이다 —
`⟦q/v→e⟧ σ ↔ ⟦q⟧ (σ[v := ⟦e⟧ σ])` (`substitution_single`). 1장에서 §1.4 를 통째로
들여 치환 정리를 증명한 이유가 이 한 줄이다.

### 명세의 자유 변수

`FV({p} c {q}) = FV(p) ∪ FV(c) ∪ FV(q)` 다. §3.6 의 변수 선언 규칙과 §3.7 의 치환 규칙이
이것을 쓴다. 2장의 `Comm.fv` 와 1장의 `Assert.fv` 를 합치면 끝이라 새로 만들 것은 없다.

## §3.2 추론 규칙

### 규칙의 모양

1장 §1.3 과 같다. 전제가 위, 결론이 아래, 메타변수가 있는 **꼴(scheme)** 이고 실제로
쓰이는 것은 그 사례(instance)다. 규칙이 **건전(sound)** 하다는 것은 모든 사례에서 전제가
타당하면 결론도 타당하다는 뜻이다.

Lean 에서는 §1.3 의 `Proof` 와 똑같이 한다 — 규칙 하나가 생성자 하나인 귀납 술어.

```lean
-- ANCHOR: hoare
/--
부분 정확성의 추론 체계. 생성자 하나가 규칙 하나다.

전제가 인자, 결론이 결과 타입 — Lean 의 화살표가 Reynolds 의 가로선이다.
-/
inductive Hoare : Assert V → Comm V → Assert V → Prop where
  /-- `{p} skip {p}` -/
  | skip (p : Assert V) : Hoare p .skip p
  /-- 대입 공리. **거꾸로** 간다 — 사후조건에서 사전조건을 만든다 (§3.3). -/
  | assign (q : Assert V) (v : V) (e : IntExp V) :
      Hoare (q /[v := e]) (.assign v e) q
  /-- 순차 합성. 가운데 단언 `r` 이 이음매다. -/
  | seq {p r q : Assert V} {c₀ c₁ : Comm V} :
      Hoare p c₀ r → Hoare r c₁ q → Hoare p (.seq c₀ c₁) q
  /-- 조건. 각 가지가 조건의 참·거짓을 사전조건에 더해 받는다. -/
  | ite {p q : Assert V} {b : BoolExp V} {c₀ c₁ : Comm V} :
      Hoare (p ⋀ b.toAssert) c₀ q → Hoare (p ⋀ ¬b.toAssert) c₁ q →
      Hoare p (.ite b c₀ c₁) q
  /-- 반복. `i` 가 **불변식**(invariant)이다 (§3.5). -/
  | wh {i : Assert V} {b : BoolExp V} {c : Comm V} :
      Hoare (i ⋀ b.toAssert) c i → Hoare i (.wh b c) (i ⋀ ¬b.toAssert)
  /-- 변수 선언. 지역 변수는 밖의 단언에 나오지 않아야 한다 (§3.6). -/
  | newvar {p q : Assert V} {v : V} {e : IntExp V} {c : Comm V}
      (hp : v ∉ p.fv) (hq : v ∉ q.fv) (he : v ∉ e.fv) :
      Hoare (p ⋀ (.cmp .eq (.var v) e)) c q → Hoare p (.newvar v e c) q
  /-- 결과 규칙. 사전조건은 강하게, 사후조건은 약하게 바꿔도 된다 (§3.2). -/
  | conseq {p p' q q' : Assert V} {c : Comm V} :
      Stronger p' p → Hoare p c q → Stronger q q' → Hoare p' c q'
-- ANCHOR_END: hoare
```

`b.toAssert` 는 §2.2 에서 만든 불 식 → 단언 변환이다 (`boolExp_eval_iff` 가 뜻을 잇는다).
`⋀` 는 `Assert.bin .and` 의 표기다. 2장 DSL 과 겹치지 않게 고른다.

Reynolds 는 결과 규칙을 둘로 나눈다 — 전제 강화(strengthening precedent)와 결론
약화(weakening consequent). 하나로 합쳐도 되고 둘로 두어도 된다. 둘로 두면 Reynolds 의
유도를 그대로 옮길 수 있고, 하나로 합치면 유도가 짧아진다. **둘 다 두고 하나를 다른 것으로
유도**하는 정리를 붙이면 관계가 드러난다.

### ★ 결과 규칙의 전제는 "타당하다" 다

`conseq` 의 전제 `Stronger p' p` 는 `∀ σ, ⟦p'⟧ σ → ⟦p⟧ σ` 다. 단언 사이의 함의가
**타당**하다는 의미적 사실이지, 1장의 `Proof` 로 증명했다는 것이 아니다.

이 선택이 이 장 전체의 성격을 정한다. Hoare 논리는 단언 논리를 **오라클로 쓴다.**
"`p'` 가 `p` 보다 강하다" 를 누가 어떻게 확인하느냐는 Hoare 논리의 관심 밖이다. 그래서
Hoare 논리의 완전성을 말할 때 "단언의 타당성에 상대적으로(relative to)" 라는 단서가
붙는다 — Cook 의 상대 완전성이다 (§3.10).

1장 §1.3 에서 `∀`-도입이 규칙이지 함의가 아니라고 했던 것과 같은 결의 구분이다. 규칙의
전제는 메타 수준의 사실이고 `⇒` 는 객체 언어 안의 연결사다. `conseq` 의 전제도 메타
수준이다.

### 건전성

```lean
-- ANCHOR: sound
/-- **건전성.** 유도된 명세는 타당하다. 규칙마다 1·2장의 정리 하나가 받친다. -/
theorem Hoare.sound {p q : Assert V} {c : Comm V} : Hoare p c q → PartialCorrect p c q
-- ANCHOR_END: sound
```

`Hoare` 에 대한 구조적 귀납이고, 절마다 쓰는 정리가 정해져 있다. 이 장 서두의 표가
그 대응이다. 각 절을 §3.3 · §3.5 · §3.6 에서 따로 본다.

**건전성은 규칙마다 독립이다.** 한 규칙의 건전성이 다른 규칙의 건전성에 기대지 않는다.
그래서 `Hoare.sound` 의 각 절을 따로 떼어 정리로 두고 (`assign_sound`, `wh_sound`, …)
연습으로 낼 수 있다 — 연습 독립성 원칙에 맞는다.

## §3.3 대입과 순차 합성

### ★ 대입 공리가 거꾸로인 이유

```
{ q/v→e } v := e { q }
```

사후조건 `q` 에서 사전조건을 **만든다.** 방향이 거꾸로라 처음 보면 어색하지만, 이유는
정확하다. 대입 뒤에 `q` 가 참이려면, 대입 전에 "`v` 자리에 `e` 를 넣은 `q`" 가 참이어야
한다 — 대입이 `v` 를 `e` 의 값으로 바꾸므로.

```lean
theorem assign_sound (q : Assert V) (v : V) (e : IntExp V) :
    PartialCorrect (q /[v := e]) (.assign v e) q := by
  intro σ hp τ hτ
  -- hτ : some (σ[v := ⟦e⟧ σ]) = some τ
  -- hp : ⟦q /[v := e]⟧ σ
  -- 명제 1.4 : ⟦q /[v := e]⟧ σ ↔ ⟦q⟧ (σ[v := ⟦e⟧ σ])
  ...
```

증명이 `substitution_single` 한 줄이다. **1장 §1.4 의 치환 정리가 이 공리 하나를 위해
있었다** 고 해도 지나치지 않다. 포획 회피가 왜 필요했는지도 여기서 다시 보인다 —
`q` 에 `∃y. …` 가 있고 `e` 에 `y` 가 자유로우면 순진한 치환은 틀린 사전조건을 만든다.

앞으로 가는 판도 있다 (Floyd).

```
{ p } v := e { ∃ v₀. p/v→v₀ ∧ v = e/v→v₀ }
```

대입 전의 값을 `v₀` 라는 새 변수로 기억해 두는 방식이다. 옳지만 사후조건에 `∃` 와 신선한
변수가 들어와 다루기 나쁘다. 뒤로 가는 판은 `q` 에 아무것도 덧붙이지 않는다.

```lean
/-- 앞으로 가는 판도 건전하다. `v₀ ∉ FV(p) ∪ FV(e) ∪ {v}` 가 필요하다. -/
theorem assign_forward_sound (p : Assert V) (v v₀ : V) (e : IntExp V)
    (h₀ : v₀ ∉ p.fv) (h₁ : v₀ ∉ e.fv) (h₂ : v₀ ≠ v) :
    PartialCorrect p (.assign v e)
      (.quant .ex v₀ ((p /[v := .var v₀]) ⋀ (.cmp .eq (.var v) (e /[v := .var v₀]))))

/-- 둘 중 하나로 다른 하나를 유도할 수 있다. 결과 규칙과 §3.7 의 ∃ 규칙이 든다. -/
theorem assign_forward_derivable : ...
```

두 판을 나란히 놓고 "왜 Hoare 는 뒤로 가는 판을 골랐나" 를 두 정리로 답하는 것이
`Assign.lean` 의 일이다.

### 순차 합성

```
{ p } c₀ { r }    { r } c₁ { q }
-------------------------------
       { p } c₀ ; c₁ { q }
```

건전성은 `Option.bind` 다. `c₀` 가 끝나면 `r` 이고, 거기서 `c₁` 이 끝나면 `q` 다.
어느 쪽이든 발산하면 공허하다.

가운데 단언 `r` 은 규칙에 **주어지지 않는다.** 유도하는 사람이 골라야 한다. 이것이
§3.4 주석 명세의 핵심이다 — 주석은 이 `r` 들을 적어 둔 것이다.

`skip` 규칙 `{p} skip {p}` 는 정의 그대로다.

## §3.4 주석 명세

`{p} c {q}` 의 유도 나무는 크다. Reynolds 는 그것을 **명령 안에 단언을 끼워 넣은** 모양으로
줄여 적는다.

```
{ x = a ∧ y = b }
t := x ;
{ t = a ∧ y = b }
x := y ;
{ t = a ∧ x = b }
y := t
{ y = a ∧ x = b }
```

순차 합성의 이음매 `r` 과 반복의 불변식 `i` 만 적으면 나머지는 규칙이 정한다. 대입 공리는
사후조건에서 사전조건을 계산하고, 결과 규칙은 이음매에서 부등식을 확인한다.

### 설계 — 유도 나무가 곧 주석이다

가장 값싼 길: `Hoare` 의 항 자체가 주석 명세다. Lean 의 `Hoare.seq (Hoare.assign _ _ _)
(Hoare.assign _ _ _)` 를 읽으면 이음매가 보인다. 예제(§3.8, §3.9)는 이 길로 간다.

### 심화 — 검증 조건 생성기

주석 명세를 **검사 가능한 대상**으로 만들 수도 있다. 명령에 이음매와 불변식만 붙인
구문 `Annot` 을 두고, 거기서 "확인해야 할 부등식들" 을 뽑아 내는 함수를 만든다.

```lean
/-- 주석 명령. 이음매(`seq`)와 불변식(`wh`)만 사람이 적는다. -/
inductive Annot (V : Type u) where
  | assign : V → IntExp V → Annot V
  | skip
  | seq : Annot V → Assert V → Annot V → Annot V     -- 가운데 단언
  | ite : BoolExp V → Annot V → Annot V → Annot V
  | wh : Assert V → BoolExp V → Annot V → Annot V     -- 불변식
  | newvar : V → IntExp V → Annot V → Annot V

def Annot.erase : Annot V → Comm V

/-- 사후조건에서 뒤로 가며 사전조건을 계산하고, 도중에 확인할 부등식을 모은다. -/
def Annot.vcg : Annot V → Assert V → Assert V × List (Assert V × Assert V)

/-- 모은 부등식이 전부 타당하면 유도가 있다. -/
theorem Annot.vcg_sound (a : Annot V) (q : Assert V) :
    (∀ vc ∈ (a.vcg q).2, Stronger vc.1 vc.2) → Hoare (a.vcg q).1 a.erase q
```

`vcg` 는 대입에서 치환하고, 순차 합성에서 이음매를 쓰고, 반복에서 불변식으로 사전조건을
바꾸며 `i ∧ b ⇒ …` 꼴 의무를 남긴다. 실제 검증 도구(Dafny, Why3)가 하는 일의 축소판이다.
분량이 있으므로 **선택**이다. 하되, 이것이 있으면 §3.8·§3.9 의 예제가 "부등식 몇 개를
`omega` 로 닫는다" 로 줄어든다.

## §3.5 `while` 규칙

### 부분 정확성 — 불변식

```
{ i ∧ b } c { i }
---------------------------
{ i } while b do c { i ∧ ¬b }
```

`i` 가 **불변식**이다. 한 바퀴를 돌아도 유지되면 몇 바퀴를 돌아도 유지되고, 루프가 끝난
자리에서는 조건이 거짓이다.

### ★ 건전성은 Scott 귀납법이다

`⟦while b do c⟧ = fix (whileF b ⟦c⟧)` 다. `while` 규칙이 건전하다는 것은 이 최소
고정점이 부분 정확성을 만족한다는 것이고, 그것은 §2.4 의 `scott_induction` 이 정확히
주는 것이다.

```lean
theorem wh_sound {i : Assert V} {b : BoolExp V} {c : Comm V}
    (hbody : PartialCorrect (i ⋀ b.toAssert) c i) :
    PartialCorrect i (.wh b c) (i ⋀ ¬b.toAssert) := by
  -- 성질: `w` 가 `i` 에서 출발해 끝나면 `i ∧ ¬b` 다.
  refine scott_induction (whileF_monotone b c.eval)
    (P := fun w => ∀ σ, ⟦i⟧ₐ σ → ∀ τ, w σ = some τ → ⟦i ⋀ ¬b.toAssert⟧ₐ τ)
    ?adm ?bot ?step
  · -- 허용 가능: 평평한 사슬의 극한은 어느 항이다 (`Chain.flat_lub_mem_range`).
  · -- ⊥ : 끝나지 않으므로 공허.
  · -- 한 바퀴 : 조건 참이면 본체가 `i` 를 지키고(전제) 나머지에 넘긴다(가설).
    --          조건 거짓이면 그 자리에서 `i ∧ ¬b` 다.
```

세 의무가 각각 §3.1 에서 말한 것과 맞물린다. 허용 가능성이 "`⊥` 는 모든 사후조건을
만족한다" 의 사슬 판이고, 시작 조건이 그 자체이고, 한 걸음이 규칙의 전제다.

§2.5 의 명제 2.6 과 §2.5 의 명제 2.7 도 `while` 절을 Scott 귀납법으로 닫았다. 같은
원리를 세 번째로 쓰는 셈이고, 이번에는 성질이 두 상태의 관계가 아니라 **한 상태의
술어**라 더 단순하다.

> Reynolds 는 §2.4 에서 이 원리에 이름을 붙이지 않았다. 그러나 §3.5 의 `while` 규칙이
> 건전하다는 것을 그가 어떻게 논증하든, 그 논증은 근사 `Fⁿ(⊥)` 에 대한 귀납과 극한으로의
> 이행이고, 그것이 Scott 귀납법이다. 2장에서 이름을 붙여 둔 덕에 3장에서 한 줄로 부른다.

### 전체 정확성 — 변항

```
[ i ∧ b ∧ e = z ] c [ i ∧ e < z ]       i ∧ b ⇒ 0 ≤ e
-------------------------------------------------------   z ∉ FV(i, b, c, e)
              [ i ] while b do c [ i ∧ ¬b ]
```

`e` 가 **변항**(variant)이다. 한 바퀴마다 줄고 0 아래로 못 내려가므로 무한히 돌 수 없다.
`z` 는 한 바퀴 시작 때의 `e` 값을 붙들어 두는 신선한 변수다 — "줄었다" 를 말하려면 전과
후를 비교해야 하고, 그러려면 전의 값을 어딘가에 기억해야 한다. 유령 변수(§3.10)의 첫 등장이다.

책의 정확한 진술은 대조가 필요하다. 변항을 자연수 값으로 두는지, `0 ≤ e` 를 별도 전제로
두는지가 판본마다 다르다. 위는 정수 위에서 쓰는 표준형이다.

### ★ 건전성은 정초 귀납이다

```lean
theorem whT_sound {i : Assert V} {b : BoolExp V} {c : Comm V} {e : IntExp V} {z : V}
    (hz : z ∉ i.fv ∧ z ∉ b.fv ∧ z ∉ c.fv ∧ z ∉ e.fv)
    (hbody : TotalCorrect (i ⋀ b.toAssert ⋀ (.cmp .eq e (.var z))) c
                          (i ⋀ (.cmp .lt e (.var z))))
    (hnonneg : Stronger (i ⋀ b.toAssert) (.cmp .le (.num 0) e)) :
    TotalCorrect i (.wh b c) (i ⋀ ¬b.toAssert) := by
  -- 측도 `(⟦e⟧ σ).toNat` 에 대한 강한 귀납.
  -- 조건 거짓 : 그 자리에서 끝난다.
  -- 조건 참   : 본체가 끝나고(전제) `e` 가 줄었으므로 측도가 줄고, 귀납 가설이 나머지를 준다.
```

Scott 귀납법이 아니다. §3.1 에서 말했듯 "끝난다" 는 극한으로 올라가지 않으므로, 단계를
세는 측도가 있어야 한다. 그 측도가 변항이다. 2장에서 `while` 의 값을 실제로 계산할 때
쓴 수법(§2.6 `forWhile_eq_fold`, §2.8 `countLoop_eval`, 연습 2.3·2.5)이 정확히 이것이다 —
그때는 구체적인 루프의 측도를 손으로 잡았고, 이제는 규칙이 측도를 인자로 받는다.

전제에서 `z ∉ FV(c)` 가 필요한 이유는 §2.5 명제 2.6(b) 다. 본체가 `z` 를 안 건드려야
"전의 값" 이 살아남는다. 상수 규칙(§3.7)과 같은 사정이다.

전체 정확성 체계 `HoareT` 는 `Hoare` 와 `wh` 규칙만 다르다. 나머지 규칙은 종료를 그대로
물려주므로 건전성 증명도 부분 판을 그대로 따른다.

## §3.6 변수 선언 규칙

```
{ p ∧ v = e } c { q }
-------------------------------   v ∉ FV(p) ∪ FV(q) ∪ FV(e)
{ p } newvar v := e in c { q }
```

안쪽에서 `v` 는 `e` 의 값으로 시작하고, 밖의 `p`·`q` 는 `v` 를 모른다.

건전성에 드는 것:

- `⟦newvar v := e in c⟧ σ = restore v σ (⟦c⟧ (σ[v := ⟦e⟧ σ]))` (§2.2).
- 갱신된 상태에서 `p` 가 여전히 참 — `v ∉ FV(p)` 와 명제 1.1 (`coincidence_assert`).
- 갱신된 상태에서 `v = e` 가 참 — `v ∉ FV(e)` 라 `e` 의 값이 안 변한다 (`coincidence_intExp`).
- 복원된 상태에서 `q` 가 여전히 참 — `v ∉ FV(q)` 와 명제 1.1.

세 신선함 조건이 각각 다른 자리에서 쓰인다. §2.6 의 `forV3_eq_fold` 에서 `w ∉ FV(e₀)`
가 필요했던 것과 같은 모양이다.

`v` 가 `p` 나 `q` 에 나오면 어떻게 하나? **이름을 바꾼다.** §2.5 의 `Comm.newvar_rename`
이 결합자를 신선한 이름으로 바꿔도 뜻이 같음을 보장하므로, 규칙을 신선한 결합자에
적용하고 그 등식으로 옮겨 오면 된다. 규칙에 신선함 조건을 붙이는 것과 α-변환이 한
짝이라는 것이 1장 §1.4 부터 이어지는 주제다.

## §3.7 더 많은 규칙

Reynolds 가 §3.7 에 모아 둔 규칙들이다. 의미 수준에서 증명하면 `Hoare` 에 생성자를 더하지
않고도 쓸 수 있고, `Hoare` 안에서 유도되는지 여부가 따로 물음이 된다.

### 상수 규칙 (rule of constancy)

```
{ p } c { q }
-----------------------   FA(c) ∩ FV(r) = ∅
{ p ∧ r } c { q ∧ r }
```

`c` 가 건드리지 않는 변수에 대한 주장은 `c` 를 지나도 그대로다. 건전성은 명제 2.6(b)
(`eval_agree_outside_fa`) 로 `r` 의 자유 변수가 안 변했음을 얻고 명제 1.1 로 `r` 의 진릿값이
안 변했음을 얻는다.

이 규칙이 §2.5 에서 자유 변수를 읽기와 쓰기로 갈랐던 이유의 정면이다. `FV(r)` 이 아니라
`FA(c)` 와의 서로소를 요구한다 — `c` 가 `r` 의 변수를 **읽는** 것은 괜찮다.

### 연언 · 선언 규칙

```
{ p₀ } c { q₀ }   { p₁ } c { q₁ }              { p₀ } c { q }   { p₁ } c { q }
-------------------------------                -------------------------------
{ p₀ ∧ p₁ } c { q₀ ∧ q₁ }                      { p₀ ∨ p₁ } c { q }
```

의미 수준에서 자명하다. `Hoare` 안에서 유도되는지는 그렇지 않다 — 두 유도를 하나로 합칠
규칙이 체계에 없기 때문이다. 이 간극이 "의미적으로 건전한 규칙" 과 "체계에서 유도되는
규칙" 의 차이이고, §3.10 의 완전성 물음이 여기서 시작된다.

### 유령 변수의 ∃ 규칙

```
{ p } c { q }
--------------------------   v ∉ FV(c) ∪ FV(q)
{ ∃v. p } c { q }
```

사전조건에서만 쓰인 변수는 존재 양화로 감출 수 있다. 앞으로 가는 대입 규칙(§3.3)의
사후조건에 든 `∃v₀` 가 어디서 왔는지가 이것으로 설명된다.

### ★ 치환 규칙 — 연습 2.8 이 여기서 값을 한다

```
{ p } c { q }
------------------------------   δ : 변수 → 변수,  δ 가 FA(c) 위에서 단사
{ p/δ } c/δ { q/δ }
```

명세의 변수 이름을 통째로 바꿔도 된다는 규칙이다. 프로시저가 없는 이 장에서는 쓸 일이
적지만, 뒤의 장에서 호출 자리에 명세를 맞출 때 이 규칙으로 인자를 바꿔 끼운다.

건전성은 §2.5 의 치환 정리(명제 2.7)와 1장의 치환 정리(명제 1.3)를 합친 것이다.
그런데 명제 2.7 의 원래 진술은 `δ` 가 **`FV(c)` 전체에서** 단사일 것을 요구한다.
그 조건으로는 `p` 와 `q` 에서 읽기만 하는 변수를 합치는 흔한 사용법이 막힌다.

연습 2.8 이 조건을 `FA(c)` 위의 단사로 약화했다 (`Comm.substitution_weak`). 그 약한 판이
이 규칙에 정확히 맞는다. **2장에서 조건을 약화하라고 한 연습이 3장의 규칙 하나를 위한
준비였다.**

## §3.8 · §3.9 예제

두 예제를 끝까지 유도한다. 하나는 구문 단언으로, 하나는 의미 단언으로.

### 피보나치 (§3.8)

```
{ n ≥ 0 }
k := 0 ; f := 0 ; g := 1 ;
{ 0 ≤ k ≤ n ∧ f = fib k ∧ g = fib (k+1) }        -- 불변식
while k ≠ n do
  { … ∧ k ≠ n }
  t := f + g ; f := g ; g := t ; k := k + 1
  { 불변식 }
{ f = fib n }
```

`fib` 는 단언 언어에 없다. 여기서 선택이 갈린다.

- 불변식을 **의미 단언**으로 쓴다. `fun σ => σ f = Nat.fib (σ k).toNat ∧ …`. 가장 정직하다.
- 아니면 `fib` 를 **관계로 풀어 쓴다.** 단언에 `fib` 가 없어도 "`f`·`g` 가 연속한 두
  피보나치 수다" 를 `∃` 와 산술로 적을 수는 있지만 길고 읽기 어렵다.

의미 단언으로 가되, 대입 공리는 구문 판(`Hoare.assign`)이 아니라 의미 판을 쓴다.
`Examples/Fib.lean` 이 이 판단을 docstring 에 적는다.

`#guard` 로 `Comm.run` 이 실제로 피보나치 수를 내는 것을 함께 본다 — 명세가 맞고 증명이
있어도 실행이 보이면 더 낫다.

### 빠른 거듭제곱 (§3.9)

```
{ n ≥ 0 }
y := 1 ; x := a ; k := n ;
{ y · x^k = a^n ∧ k ≥ 0 }                          -- 불변식
while k > 0 do
  if k mod 2 = 1 then (y := y · x ; k := k - 1)
  else (x := x · x ; k := k / 2)
{ y = a^n }
```

불변식에 거듭제곱이 든다. `Assert` 로는 못 적는다. 의미 단언으로 쓴다. 그리고 `mod` 와
`/` 도 `IntExp` 에 없으므로 §2.7 의 축소판처럼 **이 예제만의 확장**이 필요하거나, 아니면
`k mod 2 = 1` 을 `∃ j. k = 2j + 1` 로 풀어야 한다. 후자는 `IntExp` 안에서 되지만 조건식
`BoolExp` 에 `∃` 가 없으니 결국 확장이 필요하다.

이 걸림이 §3.10 의 요점이다. **명세를 적는 언어가 프로그램을 적는 언어보다 풍부해야
한다.** Reynolds 는 이 장에서 단언에 수학 기호를 자유롭게 쓰는데, 형식화하면 그 자유가
어디서 나오는지 정확히 짚어야 한다.

설계: 이 예제를 위해 `IntOp` 에 `div`·`rem` 을 더하지 않는다 (§2.7 의 결정과 같다).
대신 조건을 `k` 의 홀짝을 나타내는 보조 변수로 바꾸거나, 예제를 `2` 로 나누는 대신
`k := k - 1` 을 두 번 하는 느린 판으로 대체하고 "빠른 판이 왜 이 언어로 안 적히는가" 를
docstring 에 남긴다. 어느 쪽이든 §3.10 으로 넘어가는 다리가 된다.

## §3.10 복잡한 점과 한계

### ★ 완전성은 조건부다

건전성의 역이 완전성이다. 타당한 명세는 모두 유도되는가?

답은 **아니오**, 그리고 **조건부로 예** 다.

- **아니오** — 결과 규칙의 전제가 단언의 타당성이고, 정수 산술을 포함한 단언의 타당성은
  괴델 불완전성 정리에 의해 완전한 공리계가 없다. 그러므로 "유도" 를 단언 논리의 증명까지
  포함해 세면 Hoare 논리는 완전할 수 없다.
- **조건부로 예** — 단언의 타당성을 **오라클**로 두면 (우리 `conseq` 가 그렇게 한다)
  완전성이 성립한다. Cook (1978) 의 **상대 완전성**(relative completeness)이다. 단, 단언
  언어가 **표현력이 충분**해야 한다 — 모든 명령과 사후조건에 대해 최약 사전조건을 단언으로
  적을 수 있어야 한다.

우리 `Assert` 는 정수 산술과 양화사를 갖고 있어 이론적으로는 표현력이 충분하다 (괴델의
β-함수로 유한 수열을 부호화하면 반복의 최약 사전조건을 적을 수 있다). 그러나 그것을
Lean 으로 형식화하는 것은 이 장의 범위를 한참 넘는다. 그래서 **완전성은 `while` 없는
조각에 대해서만 증명한다.** 거기서는 최약 사전조건이 치환만으로 계산된다.

### 최약 사전조건 — 의미와 구문

```lean
/-- 의미적 최약 자유 사전조건(weakest liberal precondition). -/
def wlp (c : Comm V) (Q : State V → Prop) : State V → Prop :=
  fun σ => ∀ τ, c.eval σ = some τ → Q τ

/-- 부분 정확성은 wlp 로 다시 쓰인다. 정의 그대로다. -/
theorem partialCorrectS_iff_wlp : PartialCorrectS P c Q ↔ ∀ σ, P σ → wlp c Q σ
```

`while` 없는 조각에서는 wlp 가 **구문**으로 계산된다 (Dijkstra).

```lean
/-- `while` 없는 명령의 최약 사전조건. 치환만으로 계산된다. -/
def Comm.wp : Comm V → Assert V → Option (Assert V)
  | .assign v e, q => some (q /[v := e])
  | .skip, q => some q
  | .seq c₀ c₁, q => c₁.wp q >>= c₀.wp
  | .ite b c₀ c₁, q => do
      let p₀ ← c₀.wp q; let p₁ ← c₁.wp q
      pure ((b.toAssert ⇒ p₀) ⋀ (¬b.toAssert ⇒ p₁))
  | .wh _ _, _ => none                                 -- 여기서 막힌다
  | .newvar v e c, q => …                              -- 신선함 조건 처리

theorem wp_sound : c.wp q = some p → Hoare p c q
theorem wp_weakest : c.wp q = some p → PartialCorrect p' c q → Stronger p' p
/-- `while` 없는 조각의 완전성. -/
theorem complete_loopFree : c.wp q = some p → PartialCorrect p' c q → Hoare p' c q
```

`wp_sound` 와 `wp_weakest` 를 합치면 `while` 없는 조각의 상대 완전성이다. `wh` 절에서
`none` 이 나오는 그 자리가 표현력이 필요한 자리다.

### ★ wlp 는 최대 고정점이다

2장에서 `while` 의 **뜻**은 최소 고정점이었다. 그런데 `while` 의 **최약 사전조건**은
최대 고정점이다.

```
wlp (while b do c) Q  =  νX. (¬b ∧ Q) ∨ (b ∧ wlp c X)
```

풀기 방정식의 모양은 같은데 고르는 해가 반대다. 이유는 부분 정확성이 비종료를 **허용**
하기 때문이다. 발산하는 입력에 대해서는 사전조건이 참이어도 상관없으므로, 가장 **너그러운**
(최대) 해가 최약 사전조건이다. 전체 정확성의 최약 사전조건 `wp` 는 반대로 최소 고정점이다
— 발산을 허용하지 않으니 가장 **인색한** 해다.

상태 변환기의 정보 순서에서 `⊥` 가 아래에 있는 것과, 술어의 함의 순서에서 "모든 것을
허용" 이 위에 있는 것이 서로 뒤집힌 상이다. 2장의 `fix` 와 3장의 wlp 를 나란히 두면 그
쌍대성이 보인다. `Wlp.lean` 에서 `wlp (wh b c) Q` 가 그 방정식을 만족하고 가장 큰 해임을
증명한다 — `fix_least` 의 거울상이다.

### 유령 변수

`{ x = a } x := x + 1 { x = a + 1 }` 에서 `a` 는 프로그램 변수가 아니다. 대입 전의 값을
기억하려고 둔 **유령 변수**(ghost / logical variable)다. 명세에는 나오지만 명령에는
안 나오고, 그래서 값이 안 변한다.

우리 형식화에서는 유령 변수도 `V` 의 원소다 — 단언과 명령이 같은 변수 집합을 쓴다.
"유령" 이라는 것은 타입이 아니라 **`FA(c)` 에 없다**는 성질이다. 상수 규칙과 전체 정확성
`while` 규칙의 `z ∉ FV(c)` 가 그것을 요구한다. 유령 변수를 따로 타입으로 가르는 설계도
있지만, 이 장에서는 §2.5 의 `FA` 하나로 충분하다.

### 산술 오류와의 관계

§2.7 에서 나눗셈을 전함수로 만들었다. 그 덕에 이 장의 규칙에 "식이 정의된다" 는
전제가 없다. 오류를 `⊥` 나 별도 결과로 두었다면 대입 공리부터 조건이 붙었을 것이다.
§2.7 의 결정이 여기서 보수를 받는다.

### 이 장이 다루지 않는 것

배열(4장)이 들어오면 대입 공리가 깨진다 — `a[i] := e` 는 `a[j]` 의 값도 바꿀 수 있다
(`i = j` 일 때). 별칭이다. §2.5 에서 치환 정리를 깨뜨린 그 별칭이 대입 공리도 깨뜨린다.
프로시저(뒤의 장)가 들어오면 치환 규칙과 상수 규칙이 호출 규칙의 재료가 된다.

## 이 장에서 학습자가 얻는 것

1. **명세의 뜻은 새 의미론이 아니다** — 2장의 `Comm.eval` 에 단언 둘을 붙인 것이다.
2. **`⊥` 는 모든 사후조건을 만족한다** — 부분 정확성이 왜 사슬의 극한을 통과하는지,
   그래서 왜 `while` 규칙이 Scott 귀납법인지.
3. **대입 공리는 명제 1.4 다** — 1장 §1.4 의 치환 정리가 이 한 규칙을 위해 있었다.
4. **규칙의 전제는 타당성이다** — Hoare 논리가 단언 논리를 오라클로 쓴다는 것, 그래서
   완전성이 "상대적" 이라는 것.
5. **부분과 전체는 귀납 원리가 다르다** — Scott 귀납법과 정초 귀납. 2장에서 번갈아
   쓴 두 수법이 두 규칙으로 갈라진다.
6. **자유 변수를 읽기와 쓰기로 가른 이유** — 상수 규칙, 유령 변수, 치환 규칙이 전부
   `FA` 위에 선다. 연습 2.8 의 약화가 여기서 값을 한다.
7. **명세 언어는 프로그램 언어보다 풍부해야 한다** — 빠른 거듭제곱의 불변식이 안 적히는
   경험이 표현력 논점의 실물이다.
8. **wlp 는 최대 고정점이다** — 뜻(최소)과 최약 사전조건(최대)의 쌍대성.
